# MVP Scope: GQAI Study

- 기준일: 2026-09-03
- 범위 상태: `MVP v1 구현 완료 기준선`
- 기준 릴리스: `MVP v1`

## 1. MVP 목표

첫 버전은 다음 한 가지를 증명한다.

> 강사가 하나의 모듈을 작성해 개인 또는 그룹에 배정하면, 각 학생이 자신의 카드에서 학습 상태와 결과물을 남기고, 강사가 학생별 피드백 후 완료 처리할 수 있다.

## 2. 반드시 포함할 세 가지 기능군

### P0-1. 모듈 작성과 개인별 배정

- [x] 관리자가 모듈을 초안으로 만들 수 있다.
- [x] 제목, 본문, 제목 블록, 목록, 체크리스트, 코드, 링크, 이미지, PDF를 작성할 수 있다.
- [x] 모듈을 미리보기하고 사용 가능한 버전으로 발행할 수 있다.
- [x] 발행된 버전을 복제해 새 모듈을 만들 수 있다.
- [x] 모듈을 학생 한 명, 여러 학생 또는 그룹 하나에 배정할 수 있다.
- [x] 그룹 배정 시 현재 구성원마다 개별 배정 카드가 생성된다.
- [x] 배정 후 원본을 수정해도 기존 카드 내용은 바뀌지 않는다.

### P0-2. 학생별 학습과 제출

- [x] 학생은 자신에게 배정된 카드만 본다.
- [x] 학생이 `시작 전 → 학습 중 → 수강 완료`를 기록할 수 있다.
- [x] 학생이 텍스트, URL, 이미지, 일반 파일을 한 번의 제출에 함께 포함할 수 있다.
- [x] 제출 후 제출 시각과 수정 차수가 남는다.
- [x] 재제출은 이전 제출을 덮어쓰지 않고 새 차수로 저장한다.

### P0-3. 피드백과 최종 완료

- [x] 관리자는 학생별 제출 대기 목록을 볼 수 있다.
- [x] 관리자는 텍스트와 파일을 포함한 피드백을 남길 수 있다.
- [x] 관리자는 재제출을 요청하거나 최종 완료로 처리할 수 있다.
- [x] 학생은 자신의 피드백을 확인하고 답변 또는 재제출할 수 있다.
- [x] 완료 후에도 전체 제출·피드백 이력을 시간순으로 볼 수 있다.

## 3. P0 지원 기능

| 기능               | 포함 이유               | 단순화                         |
| ------------------ | ----------------------- | ------------------------------ |
| 강사 로그인        | 관리자 작업 보호        | 관리자 1명                     |
| 학생 계정 발급     | 폐쇄형 사이트 운영      | 자유 가입·이메일 인증 없음     |
| 임시 비밀번호 변경 | 계정 보안               | 학생 셀프 비밀번호 복구 없음   |
| 학생 활성/비활성   | 수강 종료 처리          | 물리 삭제 없음                 |
| 그룹 관리          | 여러 학생 일괄 배정     | 그룹 공동 제출 없음            |
| 관리자 현황판      | 미제출·피드백 대기 파악 | 복잡한 통계 없음               |
| 비공개 파일 저장   | 과제와 피드백 첨부      | 실행 파일 차단, 기본 50MB 제한 |
| 모바일 대응        | 학생 사용성             | 네이티브 앱 없음               |

## 4. 첫 버전에서 제외하는 기능

### 명시적 Non-goal 3개

1. 결제, 수강권, 환불, 영수증
2. 실시간 화상수업, 실시간 채팅, 수업 예약
3. AI 자동 평가, 자동 채점, AI 피드백 생성

### 추가 제외 항목

- 학생 자유 회원가입
- Google·Kakao·Naver 소셜 로그인
- 이메일·문자·카카오 알림 실제 발송
- 공동 그룹 제출과 그룹 피드백
- 점수, 등급, 순위, 수료증
- 학부모 계정
- 다중 강사와 조직별 권한
- Notion 가져오기 또는 양방향 동기화
- 실시간 공동 모듈 편집
- 모듈 판매 마켓
- 다국어와 사용자별 시간대
- 모바일 네이티브 앱
- 고급 분석 대시보드

## 5. 기술 범위 결정

| 항목         | 결정     | MVP 범위                                       |
| ------------ | -------- | ---------------------------------------------- |
| 로그인       | `needed` | 강사 발급 아이디/비밀번호, 최초 변경, 로그아웃 |
| 데이터베이스 | `needed` | 사용자·그룹·모듈·배정·제출·피드백·활동         |
| 파일 업로드  | `needed` | 모듈 자료, 학생 제출, 피드백 첨부              |
| 관리자 화면  | `needed` | 계정·그룹·모듈·배정·검토                       |
| 배포         | `needed` | Vercel 운영 URL과 환경변수                     |
| 결제         | `later`  | 내비게이션과 확장 문서만                       |
| AI 기능      | `later`  | 카드 내 슬롯과 서비스 인터페이스만             |
| 일정         | `later`  | `/admin/schedule` 경로 예약만                  |
| 알림         | `later`  | 도메인 이벤트 훅과 `/notifications` 위치만     |
| 분석 도구    | `later`  | 오류 로그와 최소 운영 점검만 P0                |

## 6. 향후 기능의 ‘위치만 확보’ 정의

위치 확보는 실제 API, 테이블, 외부 서비스 연결을 의미하지 않는다.

| 미래 기능 | MVP에서 허용되는 것                            | MVP에서 금지되는 것           |
| --------- | ---------------------------------------------- | ----------------------------- |
| 알림      | 알림 아이콘 위치, 이벤트 이름 문서화           | 이메일·카카오 발송, 재시도 큐 |
| 일정      | 비활성 메뉴 또는 준비 중 화면                  | 캘린더 CRUD, 출석, 리마인더   |
| 결제      | 관리자 메뉴 위치, 모듈 경계                    | 결제사 SDK, 거래·환불 테이블  |
| AI 피드백 | 카드 내 비활성 영역, 입력/출력 인터페이스 문서 | 모델 API 호출, 자동 채점      |

미래 메뉴가 사용자 혼란을 만들면 프로덕션에서는 feature flag로 숨기고 관리자 개발 환경에서만 확인한다.

## 7. MVP 핵심 사용자 스토리

### 강사

- 강사로서 반복 과제를 모듈로 저장해 매번 다시 작성하지 않고 싶다.
- 강사로서 한 그룹에 한 번 배정하고 학생별 카드가 만들어지길 원한다.
- 강사로서 제출과 피드백 대기 학생을 빠르게 찾고 싶다.
- 강사로서 과거 제출과 피드백 이력을 잃지 않고 싶다.

### 학생

- 학생으로서 로그인 후 지금 해야 할 과제를 바로 보고 싶다.
- 학생으로서 과제 내용을 모바일에서도 읽고 완료 여부를 기록하고 싶다.
- 학생으로서 텍스트, 링크, 이미지, 파일을 한 번에 제출하고 싶다.
- 학생으로서 피드백과 재제출 요청을 놓치지 않고 확인하고 싶다.

## 8. MVP 종료 수용 기준

- [x] 관리자만 학생 계정을 생성할 수 있다.
- [x] 비활성 학생은 로그인할 수 없고 기존 기록은 유지된다.
- [x] 모듈 발행과 버전 고정이 동작한다.
- [x] 개인, 복수 학생, 그룹 배정 결과가 정확하다.
- [x] 그룹 구성원이 3명이면 학생별 배정이 정확히 3개 생성된다.
- [x] 그룹 신규 구성원에게 과거 카드가 자동 생성되지 않는다.
- [x] 학생은 다른 학생의 배정 ID를 알아도 내용을 볼 수 없다.
- [x] 학생은 네 가지 제출 유형을 조합할 수 있다.
- [x] 재제출 후 이전 버전이 보존된다.
- [x] 관리자는 재제출 요청과 최종 완료를 구분할 수 있다.
- [x] 비공개 파일은 권한 없는 URL 접근으로 열리지 않는다.
- [x] 주요 흐름이 모바일 360px 폭에서 완료된다.
- [x] 알림·일정·결제·AI 기능은 외부 호출 없이 꺼져 있다.

## 9. 출시 후 관찰할 최소 지표

개인정보가 포함되지 않는 집계만 우선 사용한다.

- 모듈 작성에서 발행까지 성공 여부
- 개인/그룹 배정 성공 및 실패 수
- 학생별 첫 열람, 수강 완료, 첫 제출 여부
- 피드백 대기 건수
- 재제출 횟수
- 최종 완료 건수
- 파일 업로드 실패율
- 권한 거부와 서버 오류 발생 수

## 10. 범위 변경 규칙

1. 새 기능은 `P0 필수`, `P1 출시 후`, `제외` 중 하나로 분류한다.
2. 기존 P0를 제거하지 않고 새 P0를 추가하려면 일정·보안·데이터 모델 영향을 함께 기록한다.
3. P0 완료 전에는 `later` 기능을 구현하지 않는다.
4. 향후 기능의 비활성 슬롯이 실제 동작을 시작하면 범위 확장으로 간주한다.
5. 한 Phase에서 완료되지 않은 요구는 다음 Phase로 조용히 넘기지 않고 실패 또는 변경으로 기록한다.
6. MVP 목표를 증명하지 않는 꾸밈 기능은 안정화 이후로 미룬다.
