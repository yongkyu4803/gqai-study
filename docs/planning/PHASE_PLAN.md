## Phase 3. Core Vertical Slice

### 목표

최소 블록과 텍스트 제출만 사용해 `모듈 작성 → 발행 → 학생 한 명에게 배정 → 학생 제출 → 관리자 피드백 → 완료`를 실제 DB에서 한 번 완주한다.

이 Phase는 기능 폭이 아니라 데이터 흐름의 정확성을 검증한다.

### 작업

- [ ] 관리자 seed 계정으로 최소 모듈 작성
- [ ] 제목·문단 중심의 초안 저장
- [ ] version 1 발행과 불변성 확인
- [ ] 학생 한 명 직접 배정
- [ ] 학생 카드 목록·상세 실제 데이터 연결
- [ ] 첫 열람·학습 시작·수강 완료 기록
- [ ] 텍스트 제출 한 차수 저장
- [ ] 관리자 검토 목록과 텍스트 피드백
- [ ] 최종 완료 처리
- [ ] 모든 단계 활동 이벤트 기록
- [ ] 성공, 빈 상태, 오류 상태 처리

### 산출물

- 실제 데이터 기반 한 개의 완결된 핵심 흐름
- 상태 전이 서버 작업
- 핵심 통합 테스트

### 완료 조건

- 한 카드의 버전, 상태, 제출, 피드백, 완료 이력이 연결된다.
- 원본 모듈 수정 후에도 배정 카드 내용이 바뀌지 않는다.
- 최종 완료 후 학생이 새 제출을 만들 수 없다.
- 같은 서버 작업을 중복 호출해도 중복 배정·제출이 생기지 않는다.

### 자동 검증

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

### 브라우저 확인

- [ ] 관리자: 새 모듈→발행→학생 1명 배정
- [ ] 학생: 카드 열기→학습 시작→수강 완료→텍스트 제출
- [ ] 관리자: 제출 확인→피드백→최종 완료
- [ ] 학생: 완료 상태와 전체 이력 확인

### 다음 Phase 진입 조건

- 핵심 세로 흐름에 mock 저장이 남아 있지 않다.
- 상태 전이와 이벤트가 테스트된다.
- 기능 폭 확장 전 권한 위험이 문서화되어 있다.

### 실패/되돌리기

- 흐름이 실패하면 이미지·파일·그룹 기능을 추가하지 않는다.
- 최소 텍스트 경로가 안정될 때까지 상태 모델과 트랜잭션을 수정한다.
